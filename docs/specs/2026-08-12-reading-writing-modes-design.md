# 読み・書きモード分離 設計

## 背景と目的

実際に3歳児が遊んだ結果、絵と見本文字を使う読み問題は進められる一方、指で文字を書く課題はまだ難しいことが分かった。現行は読みと4段階書字を一続きの必須コースとして扱うため、読めた成功まで書字で止まってしまう。

本変更では、読みの達成と書字の体験を別々に保存する。保護者が端末全体の学び方を選べるようにし、書けない時期でも五十音を順に読んで花を咲かせられるようにする。

## 世界観辞書

- 舞台: 朝のひらがなの庭
- 読みの達成: 文字の花が咲く
- 書字の達成: 花へ小さな鉛筆印が付く
- 設定名: 難易度ではなく「まなびかた」
- 読みモード: 「よむ（おすすめ）」
- 読み書きモード: 「よむ・かく」
- 禁止: 子どもへ毎文字モードを選ばせる、書字未完了で花を枯らす、点数や上手・下手を表示する

## 検討した案

| 案 | 評価 |
|---|---|
| 現行どおり読み書きを常に必須にする | 書けないだけで読めた成功と次文字への進行が止まるため不採用 |
| 毎文字、子どもに「読む／書く」を選ばせる | 3歳児には選択が多く、学習進捗も不安定になるため不採用 |
| 保護者が全体の学び方を選び、読み・書きを別保存する | 成長段階へ合わせやすく、後日書字だけ再開できるため採用 |

## 学び方の設定

「おとなの せってい」にラジオグループ「まなびかた」を追加する。

- `よむ（おすすめ）`: 絵付き導入、同じ形探し、花、任意の行復習を進める。通常導線に書字を出さない。
- `よむ・かく`: 読み達成後に4段階書字を続ける。各書字段階は後回しにできる。

子どもの本線画面にはモード選択を常設しない。設定変更は即時保存し、初期化を要求しない。

## 一文字の状態と画面遷移

### 読みの達成

`intro → shapeMatch → 読みの花` を読みの本線とする。形合わせ正解時に `readCompleted=true` を保存し、花を咲かせる。非行末文字は次文字へ進み、行末文字は既存の任意行復習を経て次の行へ進む。

行復習の正否や音声利用可否は、読み達成を取り消さない。単語コースは46文字すべての `readCompleted` で解放する。

### 「よむ」

読みの花を確認した後、そのまま次文字または行復習へ進む。書字画面は表示しない。

### 「よむ・かく」

読みの花を確認した後、次の4段階を順に表示する。

`traceWide → traceNarrow → copyWithModel → freeWrite → 書字の鉛筆印`

各書字段階に64px以上の「あとで」操作を置く。「あとで」を選ぶと、それまでの書字記録を保存したまま次文字または行復習へ進む。全4段階を実際に体験した時だけ `writingCompleted=true` とし、花へ鉛筆印を付ける。鉛筆印は字の上手さや習得判定ではなく、「4段階を体験した」印である。

### 途中のモード変更

- `よむ・かく → よむ`: 現在文字が書字段階なら、その文字の読み達成と書字途中を保存して書字を終了する。庭の「つづき」は次の未読文字または未完の行復習へ進む。
- `よむ → よむ・かく`: 本線を過去文字へ巻き戻さない。現在の未読文字から新しいモードを適用する。
- どちらの変更でも、花、現在位置、行復習、単語進捗を消さない。

### 咲いた花からの復習

- 「よむ」では、花タップで従来どおり導入と形合わせを復習する。
- 「よむ・かく」で `readCompleted=true` かつ `writingCompleted=false` の花をタップすると、最初の未体験書字段階から再開する。
- 復習書字では、本線の `currentKanaIndex`、`stage`、`rowReview` を変更せず、その文字の書字フラグと `writingCompleted` だけを保存する。
- 書字完了済みの花タップは、従来どおり読み復習を開く。書字の反復練習専用画面は今回追加しない。

## 単語コース

単語も「選ぶ・並べる」を読み達成、「書く」を追加体験として分ける。

- 「よむ」: `絵から選ぶ → 文字を並べる → 単語の花`。次の単語は並べ終えた時点で解放する。
- 「よむ・かく」: 単語の花を咲かせた後に単語書字を表示する。書字は「あとで」にできる。
- 単語書字を後回しにしても次の単語へ進める。
- 完了済みの単語花は、モードに応じて読み復習または未完書字の再開口になる。

## 保存形式と移行

意味変更を明示するため保存スキーマをv2へ上げる。

### v2の概念

- `LearningSettings.learningMode`: `reading | readingWriting`
- 文字進捗: `readCompleted` と `writingCompleted` を別に持つ
- 単語進捗: `readCompleted` と `writingCompleted` を別に持つ
- 既存の段階別フラグは、途中再開と保護者向け記録のため維持する

### v1からの移行

- `learningMode`: 旧利用者の挙動を変えないため `readingWriting`
- 文字の `readCompleted`: `completedOnce || shapeMatched`
- 文字の `writingCompleted`: `traceWideTried && traceNarrowTried && copyTried && freeWriteTried`
- 単語の `readCompleted`: `arranged`
- 単語の `writingCompleted`: `writingTried`
- 書字途中の `stage` と段階別フラグは保持する
- 不正値は既存の部分修復方針に従い、その項目だけ安全な初期値へ戻す

新規データだけを `reading` で開始する。v1保存、v2保存、不正保存、保存不能時のfallbackを別々に回帰テストする。

## UI

### 保護者画面

- 「おとと うごき」の前へ「まなびかた」を追加する。
- 2択はチェックボックスではなくラジオボタンにする。
- 「よむ」には「まずは もじを みて おぼえる」と説明する。
- 「よむ・かく」には「よんだあと ゆびで かく」と説明する。
- 進捗表では「さいた」を「よめた」に改め、「かいた」を追加する。

### 子どもの画面

- 花は読み達成を表し、書字完了済みの花だけ小さな鉛筆印を持つ。
- 鉛筆印は花や文字を隠さず、既存タップ領域64px以上を縮めない。
- 書字の「あとで」は庭へ戻る家ボタンと混同しない右向き三角の副操作にする。
- 既存の正解演出を読み・各書字段階で維持し、モード切替による無演出遷移を作らない。

## 状態と責務の分離

- Reducer: モード別遷移、読み／書き達成、後回し、v2状態の不変更新を担当する。
- Selector: 次の未読文字、行復習、単語解放、次の未読単語を読み達成から決める。
- 保存修復: v1→v2移行と不正値の部分修復を担当する。
- App: 保護者設定変更時の現在画面正規化と、復習書字の限定的な本線保存を担当する。
- UI: 設定選択、花／鉛筆印、モードに合うCTAを表示する。完了条件を独自判断しない。

## 失敗時と境界

- 保存に失敗しても現在画面では選択したモードを維持し、既存の保存queue/fallbackへ任せる。
- モード変更とリセットが競合する場合は、既存どおりリセットを優先して設定変更を無視する。
- 復習書字の保存は本線カーソルを変更しない。再読込後も元の未読文字または行復習から続ける。
- 既存v1の書字途中データを「よむ・かく」で再開した時、完了済み段階を再要求しない。
- `reducedMotion`では花・鉛筆印の動きを抑え、達成状態は静的表示で伝える。

## 受け入れ条件

- 新規進捗は「よむ」、v1進捗は「よむ・かく」で安全に再開する。
- 「よむ」では全46文字の通常導線に書字画面が出ず、形合わせ後に花が咲く。
- 46文字の読み達成だけで単語コースが解放される。
- 「よむ・かく」では4段階書字が表示され、各段階から「あとで」で次の読みへ進める。
- モード変更前後で花・現在位置・書字途中・行復習・単語進捗が失われない。
- 未完書字の花から最初の未体験段階を再開し、書字記録だけを保存できる。
- 書字完了で鉛筆印が付き、読み達成だけの花には付かない。
- 「よむ」の単語コースは選択・並べ替えで次語へ進み、単語書字を要求しない。
- 「よむ・かく」の単語書字も後回しにでき、読み進行を止めない。
- 390x844、844x390、820x1180で、設定2択、書字の「あとで」、花の鉛筆印が重ならず操作できる。
- 画面遷移、保存移行、復習限定保存は自動テストで境界を固定する。

## 非対象

- 筆跡から「上手に書けた」「習得した」を判定する新しい採点
- 誤答率や年齢からモードを自動変更する適応学習
- 子どもごとの複数プロフィール
- 読みコースと書きコースを別の庭へ分割する大規模な画面再設計
- 完了済み書字を繰り返す専用ドリル画面

## リスクと対策

- 読み達成後も旧selectorが書字を要求する: 花、次文字、単語解放の条件をpure selectorへ集約し、46文字・60語を全件検査する。
- モード変更で保存stageが矛盾する: 設定変更時のstage正規化をpure helperにし、各書字段階からの切替を表形式でテストする。
- 復習が本線を巻き戻す: 保存可能フィールドを読み／書字実績だけに限定し、current index・stage・row reviewの不変を回帰テストする。
- 旧利用者の体験が突然短くなる: v1だけは `readingWriting` へ移行し、新規初期値と分ける。
- 鉛筆印が習得評価に見える: 保護者画面で「かく れんしゅうを した」と説明し、点数や優劣表現を使わない。
- UI追加で小画面が詰まる: 子要素の実寸から配置を決め、3 viewportで境界値と原寸画面を確認する。

## 性能目標

- モード判定、次課題選択、保存移行は同期pure処理とし、ネットワーク処理を追加しない。
- 既存Canvasの30fps上限、Pointer Events、端末内保存方式を維持する。
- 進捗フィールド追加後も保存データは端末内の小さなJSON一件に収め、初期表示や操作に体感遅延を追加しない。
