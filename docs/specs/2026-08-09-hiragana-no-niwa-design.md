# 「ひらがなのにわ」完成版設計書

- 作成日: 2026-08-09
- 状態: ユーザーレビュー待ち
- 対象: GitHub Pagesで公開する、3歳児向けひらがな読み書きゲーム

## 1. 概要

「ひらがなのにわ」は、まだ文字を読めない3歳児が、音声とイラストを手掛かりにひらがなの形へ出会い、五十音順に1文字ずつ読み書きを体験するタッチゲームである。基本46文字を一通り終えるまでは単語問題を出さず、完了後に2文字の単語から段階的に進む。

サービス運営、アカウント、広告、課金、分析基盤は持たない。完成した静的アプリをGitHub Pagesで公開し、スマートフォンとタブレットの縦横表示、ホーム画面追加、オフライン再起動へ対応する。学習記録は端末内だけに保存する。

## 4. 体験原則

1. **ひらがなが主役**: 問題の最大要素は文字とし、イラストは意味づけと報酬に限定する。
2. **読めなくても分かる**: 操作説明は音声、動き、大きな絵で伝え、文字だけのCTAを置かない。
3. **間違えても終わらない**: 赤い×、警告音、残機、時間切れを使わず、補助を一段強める。
4. **一度に一つ**: 同時に複数の課題や主要CTAを出さず、次に触る対象を一つに絞る。
5. **達成が庭に残る**: 完了した文字は文字の花となり、対応する仲間や物が庭へ加わる。
6. **習得と進行を分ける**: 一通り体験すれば次へ進め、形、音、読み、なぞり、書字の習熟度は別に記録する。

## 6. 全体導線

### 6.1 初回

1. 全画面に大きなスピーカーボタンを一つだけ表示する。
2. タップで音声を有効化し、「こえが きこえたら、じょうろを さわってね」と再生する。
3. じょうろをタップすると、そのまま「あ」の導入を開始する。
4. 名前、年齢、アカウント、文字による設定説明は求めない。

### 6.2 2回目以降

1. 育った庭と中央のじょうろを表示する。
2. じょうろをタップすると、最後に未完了の文字の続きから再開する。
3. 完了済みの文字は庭の文字花から復習できる。
4. 保護者画面は画面隅の保護者マークを2秒長押ししたときだけ開く。

### 6.3 基本文字から単語への遷移

1. 「ん」の一通り体験完了後、46文字の花が庭で一度に開く。
2. 「ことばの庭」への道が現れ、音声で案内する。
3. 以後も「もじの庭」へ戻って任意の文字を復習できる。

## 7. 1文字の学習状態

1文字の状態遷移は以下とする。

`intro -> shapeMatch -> soundMatch -> traceWide -> traceNarrow -> copyWithModel -> freeWrite -> reward -> completedOnce`

| 状態 | 問題側 | 選択・操作 | 目的 |
|---|---|---|---|
| intro | 頭文字イラスト、大きな対象文字、音声 | 文字またはスピーカーをタップ | 形、音、意味へ同時に出会う |
| shapeMatch | 頭文字イラスト、大きな対象文字 | 3つの文字だけの選択肢から同じ形を選ぶ | 形の視覚的弁別 |
| soundMatch | 頭文字イラストと対象音。見本文字は隠す | 3つの文字だけの選択肢から選ぶ | 音と字形の対応 |
| traceWide | 書き順アニメーションと太い道 | 指で道をなぞる | 運筆方向と大きな形 |
| traceNarrow | 細い道または点線 | 指でなぞる | 補助を減らした運筆 |
| copyWithModel | 横に見本、白い書字面 | 見本を見て書く | 見本からの再現 |
| freeWrite | 音声と任意再生できる小さな見本 | 白い書字面へ書く | なぞらない書字体験 |
| reward | 対象文字の花とイラスト | 次のじょうろをタップ | 達成の定着 |

`freeWrite` の成功精度は次の文字への必須条件にしない。ただし、必ず一度は白紙書字を提示し、スキップした場合も保護者画面へ「未体験」と記録する。文字の進行は固定順で、問題の順番を適応的に入れ替えない。

五十音の各行（3〜5文字）が終わるたび、その行の文字だけを使った形合わせと音合わせを1回ずつ提示する。この行復習は単語問題ではない。

## 9. 選択肢の難易度

1. 初回の形合わせでは、字形が大きく異なる2文字を誤答候補にする。
2. 同一文字内の再挑戦では、色を手掛かりにしない。文字はすべて同色とする。
3. 行復習以降は「あ／お」「ぬ／め」「る／ろ」「れ／わ／ね」「は／ほ」「し／つ」など、似た字形を段階的に混ぜる。
4. 最初の誤答では音声を再生する。2回目は見本文字と正解候補を同時にゆっくり脈動させる。3回目は正解候補を案内して進める。
5. 誤答回数を子ども向け画面へ表示しない。

## 10. 単語コース

基本46文字の `completedOnce` がすべて真になった場合のみ解放する。最初は清音だけの2文字語から始め、次に清音の3文字以上、濁音・半濁音、促音・拗音へ進む。

| 段階 | 内容 | 主な遊び |
|---|---|---|
| W1 | 清音の2文字語 | 絵に合う単語を選ぶ、2文字を順に並べる、なぞる |
| W2 | 清音の3文字以上 | 1文字ずつ音を聞く、並べる、見本書き |
| W3 | 濁音・半濁音 | 点々・丸の有無を見分ける、単語を読む、書く |
| W4 | 小さい「っ」 | 音の詰まりを動きで示し、並べる、書く |
| W5 | 小さい「ゃ・ゅ・ょ」 | 2文字で一つのまとまりになる音を示し、読む、書く |

完成版は、W1からW5まで合計60語以上を収録する。各語は、3歳児がイラストから意味を推測しやすい具体物、動物、食べ物、身近な動作を優先し、表記、音声、イラスト、難易度、使用文字を1つのコンテンツ定義で管理する。

## 11. 画面とアンカー

### 11.1 共通

- 外周余白は `safe-area-inset-*` と16 CSS pxの大きい方を使う。
- 主要タッチ対象は64 CSS px以上、補助操作も48 CSS px以上とする。
- 画面は「上部HUD」「中央の主要教材」「下部の操作」の3領域へ分ける。
- HUDは上端へ、操作は下端へアンカーし、主要教材の境界へ重ねない。
- 一時文言はHUDと教材の間に専用行を確保し、絶対配置で教材へ重ねない。
- カード高さは固定せず、文字、イラスト、間隔、操作の実寸から決める。

### 11.2 縦画面

- 上部: 花びら進行と音声再生。
- 中央: 問題カード。文字を最も大きくし、イラストはその補助として横または上へ置く。
- 下部: 文字選択肢または書字面の操作。
- 画面が低い場合は教材と選択肢を均等縮小し、タッチ対象の最小寸法は維持する。

### 11.3 横画面

- 左側に問題カード、右側に選択肢または書字面を置く。
- HUDは上端全幅、主要CTAは右側領域の下端へ置く。
- 横画面への回転案内で遊びを止めず、同じ状態を保ったまま再配置する。

### 11.4 数値検証

代表画面ごとに、選択肢、スピーカー、次へボタンの `bottom` と `right` が親カード境界内に収まることをランタイムで検査する。HUD下端、一時文言下端、教材上端の間にも8 CSS px以上の安全余白を要求する。

## 12. システム構成

- **React + TypeScript**: 画面、状態表示、設定、保護者画面。
- **Canvas 2D**: なぞり線、書き順ガイド、自由書字。
- **Pointer Events**: 指、Apple Pencil、マウスを同じ入力経路で扱う。
- **学習状態機械**: 1文字内の状態と、次の文字・行復習・単語解放を純粋関数で決定する。
- **コンテンツマニフェスト**: 文字、語、音声文、イラスト、参照書字パスをデータとして管理する。
- **音声アダプター**: `speechSynthesis` の日本語音声を選択し、再生キュー、割り込み、再生不可状態を統一する。
- **進行ストア**: IndexedDBを主保存先にし、設定は小さなキーとして保存する。保存形式へ明示的なバージョンを持たせる。
- **PWA**: アプリシェル、コンテンツ、画像、効果音をキャッシュし、GitHub Pagesのサブパスで動作させる。

大きな万能コンポーネントを作らず、`learning-core`、`content`、`writing`、`audio`、`storage`、`ui` を分ける。各モジュールは公開型と純粋な入出力を持ち、ブラウザAPI依存はアダプター内へ閉じ込める。

## 13. データの流れ

1. コンテンツマニフェストから現在の文字と問題状態を読む。
2. 学習状態機械が、現在の進行と入力から次の状態を返す。
3. UIが状態を表示し、音声アダプターへ短い再生要求を送る。
4. 選択または書字結果を、形、音、なぞり、見本書き、自由書字の別指標へ反映する。
5. 状態の区切りごとに進行ストアへ保存する。
6. 46文字の `completedOnce` が揃ったときだけ単語コースを解放する。

保存データは、スキーマバージョン、現在位置、文字別の各体験状態、単語別の状態、設定だけを持つ。子どもの名前、生年月日、入力した生の筆跡履歴は保存しない。

## 14. 書字判定

対象文字は常に既知なので、全ひらがなを分類する認識器は使わず、対象文字の参照ストロークとの緩やかな比較を行う。

1. Pointer Eventsから得た点列を一定間隔へ再サンプリングする。
2. 書字領域内の位置と大きさを正規化する。
3. ストローク数、開始領域、進行方向、参照経路からの距離、主要交差・終点を評価する。
4. 点の揺れを平滑化し、子どものはみ出しを許容する。
5. 失敗判定ではなく、`strongGuide`、`gentleGuide`、`independent` の補助段階を決める。

書字結果が基準へ届かなくても次の文字を永久にロックしない。連続して難しい場合は、参照アニメーションを再生し、道幅を広げる。自由書字では、誤判定を避けるため厳密な合否を子どもへ表示しない。

## 15. 音声、効果音、オフライン

- 初回の明示タップ後に日本語音声を選択し、短い文へ分割して再生する。
- 同じ画面内の案内を重ねて再生せず、新しい案内で古いキューを取り消す。
- 文字音、紹介文、操作案内はコンテンツ定義から生成し、UIへ文言を重複させない。
- BGM、効果音、音声は個別にオン・オフできる。
- 効果音は静的ファイルとして同梱し、音声読み上げ中の音量を下げる。
- 日本語のシステム音声が利用できない場合は、画面の動きと強調で操作を継続できるようにし、保護者画面に状態を示す。
- PWAのオフライン再起動を保証する。読み上げのオフライン可否は端末にインストールされた日本語音声へ依存することを保護者画面へ明記する。

## 16. 保護者画面

- 46文字の一覧と現在位置。
- 各文字の形合わせ、音合わせ、なぞり、見本書き、自由書字の体験状態。
- 再案内が多かった文字の一覧。ただし「苦手」と断定しない。
- 音声、BGM、効果音、動きを減らす設定。
- 進行の全リセット。読み取り確認を伴う二段階操作にする。
- ブラウザ、PWA、音声、保存領域の利用状態。

## 17. エラー処理

| 状況 | 動作 |
|---|---|
| 音声が再生できない | 遊びを止めず、スピーカーを再試行状態にし、動きで次の操作を示す |
| IndexedDBへ保存できない | 現在セッションを継続し、可能なら小さな進行データを代替保存する。保護者画面へ通知する |
| 保存データの一部が壊れている | 正常なレコードを保持し、復旧できない範囲だけ初期状態へ戻す |
| ブラウザ更新・画面回転 | 完了済みの状態境界から再開し、途中の線だけ破棄する |
| 画像読み込み失敗 | 文字学習を継続し、イラスト領域へ再試行可能な代替表示を出す |
| Service Worker更新 | 新旧ファイルを混在させず、次回起動時に一括更新する |

## 18. 検証方針

### 自動確認

- 五十音の固定順と、46文字完了前に単語が解放されないこと。
- 各文字の状態遷移、再挑戦、途中復帰。
- 保存形式の新規作成、再読込、バージョン移行、部分破損。
- 書字点列の正規化、代表文字の許容例と明確な逸脱例。
- 音声キューの重複防止とキャンセル。
- PWAのGitHub Pagesサブパスとオフライン再起動。
- ブラウザコンソールに未処理例外がないこと。

### 代表画面確認

| 種別 | viewport |
|---|---|
| スマートフォン縦 | 390 x 844 |
| スマートフォン横 | 844 x 390 |
| タブレット縦 | 820 x 1180 |
| タブレット横 | 1180 x 820 |

初回、形合わせ、音合わせ、なぞり、自由書字、報酬、庭、保護者画面、単語解放を確認する。スクリーンショットは生成後に必ず目視し、主要教材と操作の重なり、上下左右のはみ出し、一時文言の位置、文字とイラストの主従を確認する。カード内部は境界値も取得して数値で確認する。

検証は上記の主要状態と代表viewportへ限定し、全端末、全問題、全設定の直積試験は行わない。

## 19. 受け入れ条件

- [ ] 初期登録なしで、最初のスピーカータップから「あ」を開始できる。
- [ ] 子ども向け主要導線に、読解しないと進めない操作がない。
- [ ] 基本46文字が五十音順に1文字ずつ進む。
- [ ] 問題側に対象文字とイラストがあり、形合わせの選択肢は文字だけである。
- [ ] 同じ形を選べた状態と、音から選べた状態を別に記録する。
- [ ] なぞり補助が太い道から白紙書字まで段階的に減る。
- [ ] 書字精度が低くても進行を永久に止めない。
- [ ] 46文字完了前に単語問題が出ない。
- [ ] 単語コースに清音、濁音、半濁音、促音、拗音を含む60語以上がある。
- [ ] 更新と再起動後も進行が残り、破損時は正常範囲を保持する。
- [ ] スマートフォンとタブレットの縦横で、主要教材と操作が重ならない。
- [ ] 書字中にページがスクロールせず、指の軌跡が欠けずに表示される。
- [ ] 書字画面は30fps以上を目標とし、入力反応50ms以内を目標とする。
- [ ] PWAとしてホーム画面へ追加でき、キャッシュ後はオフラインで再起動できる。
- [ ] ランタイムに広告、分析、アカウント、外部画像サービスへ接続しない。

## 20. 非対象

- カタカナ、漢字、ローマ字。
- 音声認識による発音採点。
- ログイン、複数ユーザー、端末間同期、クラウドバックアップ。
- ランキング、広告、課金、SNS共有。
- 保護者向けの学習時間ノルマや他児との比較。
- 全ひらがなを分類する機械学習型の手書き文字認識。

## 21. リスクと対策

| リスク | 対策 |
|---|---|
| イラストだけを見る | 文字を最大要素にし、形合わせの選択肢には文字以外を置かない |
| 書字判定の誤否定 | 対象文字との緩やかな比較に限定し、厳密な不正解を表示せず補助調整に使う |
| 読み上げ音声の端末差 | 日本語音声の選択を明示し、短文に分割し、再生不可時は動きで継続する |
| 長い教材による初回読み込み増大 | 文字行と単語段階ごとに画像を遅延読み込みし、次の教材だけ先読みする |
| 保存消失 | 状態境界ごとに保存し、スキーマ移行と部分復旧を用意する |
| 子どもの誤操作 | 主要CTAを一つに絞り、保護者画面と全リセットは長押し・二段階確認にする |
| 小画面でのはみ出し | 固定高さと比率配置を避け、実寸から配置し、代表viewportで境界値を検証する |
| PWAの古いキャッシュ | キャッシュ版を一括更新し、検証時はcache-bustingまたはService Worker削除を行う |

## 22. 性能目標

- 書字中の描画更新: 30fps以上を目標。
- タッチから軌跡表示まで: 50ms以内を目標。
- 1フレームの書字処理予算: 33.3ms未満。
- 初回JSとCSS: gzip合計500KB未満を目標。
- 最初の「あ」を遊べるまでに必要な転送量: 3MB未満を目標。
- 画像は教材単位で遅延読み込みし、次の1教材だけ先読みする。
- Docker内の自動計測値だけで実機性能を認証せず、アルゴリズム予算と代表ブラウザの動作確認を根拠にする。

## 23. 完成条件

本設計の「完成」は、受け入れ条件を満たす全46文字と60語以上の単語コース、統一された画像アセット、音声案内、書字入力、端末保存、保護者画面、PWA、GitHub Pages用ビルド、代表viewport検証が揃った状態を指す。画面だけ存在する未収録教材、仮画像、仮音声、未検証の公開物を完成扱いにしない。
